## 规则生成指南

### 阶段一：规范性检查

1. **主键、唯一标识重复**
   - 适用字段：主键字段、业务唯一标识
   - 规则：值必须全表唯一

2. **值域规范**
   - 适用字段：性别、民族、国籍、政治面貌、宗教信仰、兵役状况、证件类型
   - 规则：必须引用国家标准或行业标准
   - 示例：性别编码必须符合 GB/T 2261.1 标准

3. **格式规范**
   - 适用字段：身份证号、出生日期、手机号等
   - 规则：必须严格符合格式规范
   - 示例：
     - 身份证：当证件类型为'居民身份证'时，号码必须为18位
     - 出生日期：必须符合 YYYYMMDD 或 YYYY-MM-DD 格式

4. **文本规范**
   - 适用字段：姓名、地址、曾用名
   - 规则：不应包含首尾空格、非法特殊字符

### 阶段二：完整性与一致性检查

1. **元素完整性**
   - 核心字段（如 ID、证件号、姓名）：空值率应低于 5%
   - 非核心字段：空值率应低于 30%

2. **联合元素完整性**
   - 适用场景：姓名 + 证件号码 不能同时为空

3. **一致性规则**
   - 证件类型↔证件号码：类型为身份证时，号码必须18位
   - 性别↔身份证号：第17位奇偶性与性别一致

4. **时序关系**
   - 适用字段：出生日期
   - 规则：不应晚于当前日期

### 阶段三：合理性检查

1. **记录数量合理**
   - 维度表：每个自然人只能有一条记录

2. **测试数据**
   - 适用字段：姓名、地址等
   - 规则：不应包含'测试'、'test'、'abc'、'123'等

## 输出格式

输出必须是标准的 JSON 数组，不要包含 Markdown 标记。

每条规则包含：
- `field_name`：字段名（表级规则使用空字符串或组合字段名）
- `stage`：阶段（阶段一 / 阶段二 / 阶段三）
- `rule_name`：规则名称（严格从上述规则列表中选择）
- `rule_description`：规则描述（引用上述模板，替换字段名）
- `business_justification`：业务依据（自动生成，见下方格式）
- `remark`：备注（引用标准或说明）

### business_justification 格式

每条规则的 business_justification 使用三段式格式：

```
业务来源: 知识图谱字段 <field_name>（<business_term>，<data_standard>）
标准依据: <具体标准条款>
生成理由: <为什么生成这条规则>
```

    "remark": "关联证件类型校验"
  }

### 规则 business_justification 生成规则

1. **枚举值规则**
   - 业务来源: "知识图谱字段 {field_name}（{business_term}，{data_standard}）"
   - 标准依据: "依据 {standard}《{standard_name}》规定：{具体条款}"
   - 生成理由: "字段在知识图谱中关联国家标准"
   - 示例: "业务来源: 知识图谱字段 GENDER（性别，GB/T 2261.1）\n标准依据: GB/T 2261.1-2003《人的性别编码》第3条规定：1(男)/2(女)/0(未说明)/9(未知)\n生成理由: 字段在知识图谱中关联国家标准"

2. **格式规则（身份证）**
   - 业务来源: "知识图谱字段 ID_NO（身份证件号码，GB 11643）"
   - 标准依据: "GB 11643-1999《公民身份号码》规定：公民身份号码为18位或15位"
   - 生成理由: "字段在知识图谱中标记为核心字段（is_core_field=true）"

3. **核心字段非空规则**
   - 业务来源: "知识图谱字段 {field_name}（{business_term}）"
   - 标准依据: "无"
   - 生成理由: "字段在知识图谱中标记为核心字段（is_core_field=true），核心字段不允许缺失"

4. **唯一性规则**
   - 业务来源: "知识图谱字段 {field_name}（{business_term}，{data_standard}）"
   - 标准依据: "无（业务唯一性要求）"
   - 生成理由: "字段在知识图谱中标记为核心字段，业务上应唯一"

5. **测试数据检测**
   - 业务来源: "知识图谱字段 {field_name}（{business_term}）"
   - 标准依据: "无"
   - 生成理由: "测试数据不应进入生产环境"
